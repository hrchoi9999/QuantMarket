# QuantMarket 시장 분석 메뉴 1차 탭 구성안

작성일: 2026-04-29  
관련 시스템: QuantMarket / QuantService(redbot.co.kr)

## 1. 기본 방향

1차에서는 상단 메뉴에 `시장 분석`을 새로 추가하고,  
그 안에서 시장 정보를 몇 개의 탭으로 나눠서 보여주는 구조로 간다.

이유는 다음과 같다.

- 지금 생산되는 데이터 양이 이미 `시장 브리핑` 단일 페이지를 넘어서고 있다.
- 한 페이지에 모두 밀어 넣으면 가독성이 급격히 떨어진다.
- 사용자는 요약형 정보와 데이터 열람형 정보를 다르게 소비한다.
- 따라서 `시장 브리핑`과 `시장 분석`은 당분간 분리 운영하는 것이 좋다.

## 2. 1차 운영 원칙

### 1차
- 상단 메뉴에 `시장 분석` 추가
- `시장 분석` 안에서 여러 탭으로 정보 구분
- 기존 `시장 브리핑` 메뉴는 유지

### 2차 검토
- 실제 페이지 정보량과 사용성 확인
- `시장 브리핑`의 핵심 요약을 홈 첫 화면으로 이동할지 검토
- 필요하면 `시장 브리핑` 메뉴를 홈 landing 성격으로 재정의

즉, 지금 당장은 `시장 브리핑`을 바로 없애지 말고,
`시장 분석`이 충분히 내용이 차고 구조가 안정화된 뒤에
홈과의 관계를 다시 정리하는 것이 좋다.

## 3. 추천 메뉴 구조

### 상단 메뉴
- 홈
- 시장 분석
- 오늘의 추천
- 성과
- 변경내역
- 의견보내기
- 로그인

### 홈
- `시장 브리핑` 핵심 요약 일부만 보여줌
- 퀀트모델 시장 흐름
- 오늘 장중 흐름
- 시장 분위기 핵심 2~3줄

### 시장 분석
- 데이터/차트형 상세 페이지
- 탭 구조로 구성

## 4. `시장 분석` 1차 탭 구성 추천

현재 QuantMarket이 이미 제공 가능한 데이터 기준으로 가장 자연스러운 1차 탭은 아래 4개다.

### 탭 1. 시장 상태
- 목적:
  - 전체 시장 상태를 가장 먼저 이해하게 하는 탭
- 표시 내용:
  - 상태점수 timeline
  - trend / breadth / risk / defensive_flow score 차트
  - 상태 라벨 변화
  - 최근 상태 전이 요약
- 사용 payload:
  - `quantservice_market_timeline.json`
  - `quantservice_market_timeline_history.json`
  - `quantservice_market_state_transition.json`
  - `quantservice_market_state_transition_history.json`

### 탭 2. 자산 강도
- 목적:
  - 어떤 자산군이 상대적으로 강한지 보여줌
- 표시 내용:
  - KOSPI / KOSDAQ / GOLD / BOND / USDKRW / INVERSE 상대강도
  - 최근 20일 수익률
  - 강도 순위 변화
- 사용 payload:
  - `quantservice_market_asset_strength.json`
  - `quantservice_market_asset_strength_history.json`

### 탭 3. 장중/야간 참고
- 목적:
  - 종가 기반 정식 상태와 별도로, 지금 흐름과 다음 거래일 참고 신호를 보여줌
- 표시 내용:
  - 오늘 장중 흐름 요약
  - 장중 futures / 수급 / breadth 참고
  - 내일 시장 전망 참고
  - overnight asset history
- 사용 payload:
  - 현재 public `state_intraday_bridge`
  - `quantservice_market_next_day_preview.json`
  - `quantservice_market_next_day_preview_history.json`
- 주의:
  - 장중 참고와 정식 상태를 시각적으로 분리 표시

### 탭 4. 데이터 해설
- 목적:
  - 사용자가 지표 의미를 이해하게 도움
- 표시 내용:
  - 각 점수의 의미
  - source 설명
  - official / proxy / fallback 구분
  - 비자문 고지
- 사용 데이터:
  - manifest / descriptions / metric definitions

## 5. 탭을 이렇게 나누는 이유

### `시장 상태`와 `자산 강도`를 분리하는 이유
- 시장 상태는 종합판단 축
- 자산 강도는 cross-asset 비교 축
- 둘을 한 탭에 섞으면 초점이 흐려진다

### `장중/야간 참고`를 별도 탭으로 두는 이유
- 종가 기준 상태와 장중 참고 레이어는 성격이 다르다
- 장중 데이터는 변동성이 높고 fallback 가능성이 있다
- 사용자 혼란을 줄이려면 독립 탭이 가장 안전하다

### `데이터 해설` 탭이 필요한 이유
- 차트가 많아질수록 “이게 무슨 뜻인지”를 묻는 사용자가 늘어난다
- 특히 40~60대 사용자에게는 설명 탭이 유용하다

---

## 6. 홈과 `시장 브리핑`의 관계

현재 기준으로는 아래처럼 운영하는 것이 좋다.

### 지금
- 홈: 브리핑 요약 카드
- 시장 브리핑: 해석형 상세 페이지
- 시장 분석: 데이터/차트형 상세 페이지

### 나중 검토
- 만약 `시장 분석`이 충분히 풍성해지고
- `시장 브리핑`의 역할이 “첫 진입 요약” 쪽으로 더 명확해지면
- 홈 첫 화면을 사실상 `시장 브리핑` landing처럼 운영하는 방식이 적합할 수 있다.

즉,

- `시장 브리핑` -> 홈형 진입 페이지
- `시장 분석` -> 데이터 상세 페이지

로 재편할 가능성은 높지만,
그건 1차가 아니라 2차 판단이 더 적절하다.

## 7. 1차 공개 반영 권장안

### 공개 메뉴
- 홈
- 시장 분석
- 오늘의 추천
- 성과
- 변경내역
- 의견보내기
- 로그인

### 시장 분석 페이지 1차 탭
1. 시장 상태
2. 자산 강도
3. 장중/야간 참고
4. 데이터 해설

### 기존 시장 브리핑 처리
- 당장은 메뉴를 유지하거나
- 홈 상단 브리핑 카드로 함께 노출
- 실제 정보량과 UX를 본 뒤 홈 통합 여부 판단

---

## 8. 결론

현재 단계에서는 다음 판단이 가장 적절하다.

1. 먼저 `시장 분석` 메뉴를 만든다.
2. 그 안에 데이터 성격별로 4개 탭을 둔다.
3. `시장 브리핑`은 바로 없애지 말고 유지한다.
4. 실제 콘텐츠 밀도와 사용성을 본 뒤,
   나중에 `시장 브리핑`을 홈 landing으로 흡수할지 결정한다.

즉,  
`시장 분석`은 먼저 확장하고,  
`시장 브리핑`의 홈 통합은 그 다음에 판단하는 순서가 가장 안전하다.
